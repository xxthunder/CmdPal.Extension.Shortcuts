# [CPS-016] The title shows the file's extension

**Status**: In Progress
**Priority**: Medium
**Component**: `src/FoldersCatalog/Catalog.cs`, `src/CmdPal.Extension.Shortcuts/ShortcutsCommandsProvider.cs`
**Related**: [CPS-002b](cps-002b.md) (title and subtitle of a catalogue entry)

**Summary**:
As a user of Command Palette, I want each entry's title to be the file name with its extension, so that I can tell `wsl-manager.ps1` from its `wsl-manager.bat` wrapper and see which file starts.

**Description**:
The title is the file name without its extension, and the subtitle is the folder. A script and
its `.bat` wrapper in the same folder show the same title and the same subtitle; only the icon
tells them apart. With the extension in the title, the two read `wsl-manager.ps1` and
`wsl-manager.bat`, and an entry of this extension also stands apart from results of other
extensions with the same name, such as `wsl` of the installed apps next to `wsl.ps1`.

The title is set by each extension; Command Palette has no setting that shows or hides
extensions. The catalogue makes the name today (`Catalog.cs`, `GetFileNameWithoutExtension`).

Raised on 2026-11-17.

**Scope Decisions**:
- **Subtitle, not title** (the author, 2026-11-17): the title stays the name without extension.
  Replaced on 2026-11-24 by *Extension in the title*.
- **Wrappers stay listed** (the author, 2026-11-17): a `.bat` next to a `.ps1` of the same name is not hidden; the author deletes wrappers that are not needed.
- **Extension in the title** (the author, 2026-11-24, in the Q&A round of the loop): the title
  is the file name with its extension; the subtitle stays the folder. The full path in the
  subtitle is dropped.
- **Every entry, links too** (the author, 2026-11-24): the extension shows on every entry,
  `.lnk` and `.url` included (`Open shortcuts folder.lnk`); one rule, no exception.

**Acceptance Criteria**:
- [ ] The title of every catalogue entry is its file name with its extension
- [ ] The subtitle is unchanged: the entry's folder
