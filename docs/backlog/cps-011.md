# [CPS-011] A new user sees how to choose folders when the catalogue is empty

**Status**: In Progress
**Priority**: Medium
**Component**: `src/CmdPal.Extension.Shortcuts/Helpers/SettingsManager.cs`, `src/CmdPal.Extension.Shortcuts/ShortcutsCommandsProvider.cs`, `src/FoldersCatalog/` (the example files), `README.md`
**Related**: [CPS-010](cps-010.md) (Store release, which this item comes before), [CPS-002c](cps-002c.md) (folders and extensions as settings)

**Summary**:
As someone who installed Shortcuts from the Gallery or the Store, I want the extension to tell me how to choose my folders when it finds nothing, so that I do not take an empty catalogue for a broken extension, and to get a few example files on request, so that I see what the extension does before I fill a folder myself.

**Description**:
The default folders are `%USERPROFILE%\shortcuts\**` and `%USERPROFILE%\shortcuts_private\**`
(`SettingsManager.DefaultPatterns`), the author's own. For anyone else neither folder exists:
the extension adds nothing to the main search and gives no sign that it runs or that it has
settings. Once the extension is in the Store (CPS-010), that is the first thing a stranger
sees.

Three changes:
- **One default folder**: `%USERPROFILE%\shortcuts\**`. `shortcuts_private` is the author's
  setup; the author's shortcuts repository sets both folders when it installs the extension
  (shortcuts [SC-089](https://github.com/xxthunder/shortcuts/blob/develop/docs/backlog/sc-089.md)).
- **A hint when the catalogue is empty**: the extension lists one top-level command, e.g.
  "Shortcuts: no files found, choose your folders", that opens the extension's settings. It
  goes as soon as the catalogue holds a file, and comes back when it is empty again.
- **Example files on request**: the hint offers a second command, "Shortcuts: create example folder".
  It creates `%USERPROFILE%\shortcuts` with three files, one of each kind the extension
  handles differently:
  - `Hello.cmd`: echoes its arguments and pauses, a script that takes arguments (CPS-009);
  - `Hello.ps1`: the same in PowerShell;
  - `Open shortcuts folder.lnk`: a shortcut to the folder itself, a target every machine has
    and the place to add the user's own files.

  It never overwrites a file that exists. The names and the script contents live in
  `FoldersCatalog` and are tested there; writing the `.lnk` needs the Windows shell
  (`IShellLink`) and stays in the extension.

A changed default reaches only users without saved settings; the author's machine keeps the
folders saved in its settings file.

Raised on 2026-11-13.

**Scope Decisions**:
- **Hint over a different default** (the author, 2026-11-13): a folder everyone has, such as
  Desktop or Documents, would work at once but duplicate what Command Palette finds already
  and change the author's setup. The default stays the shortcuts folder; the hint makes the
  empty state explain itself.
- **Examples on request, not on startup** (the author, 2026-11-15): creating the folder by
  itself when it is missing was the first idea. An MSIX package has no install hook, so it
  would run on every start: a folder the user deleted on purpose would come back unless a
  "seeded once" flag were stored, and a Store app writing into the profile unasked looks like
  litter. As a command on the hint the user opts in with one click, nothing reappears after a
  deletion, and no state is needed.
- **The hint opens the settings page itself** (the loop's ruling, 2026-11-15): the hint's
  command is the toolkit's `Settings.SettingsPage`, so Enter on the hint opens the extension's
  settings form. CI's Windows build checks that it compiles.
- **PowerShell 7 is named, not worked around** (the loop's ruling, 2026-11-15): a `.ps1` runs in
  `pwsh` since CPS-009; the example `Hello.ps1` gets no fallback to Windows PowerShell 5.1. The
  README names PowerShell 7 for `.ps1` files; `Hello.cmd` works without it.
- **Examples only where they would show** (the loop's ruling, 2026-11-15): "Create example
  folder" is offered only when a configured pattern is `%USERPROFILE%\shortcuts` (flat or
  `\**`, after expansion); otherwise the examples would not appear, and the hint alone shows.
- **Found by typing the extension's name** (the author, 2026-11-16, after the first UAT): the
  UAT found both commands only when searching for "shortcuts", and the offer only by luck,
  through its subtitle, the folder path. Command Palette's empty search lists every
  extension's top-level commands in provider order below *Pinned* and *Recent*, and an
  extension cannot move or pin its own commands, so no title makes the hint visible without
  typing. Both commands' titles therefore start with "Shortcuts:", and the README tells the
  user to open Command Palette and type *Shortcuts*. A fallback command shown on every search
  was left out: it would put the extension into results where it does not belong.

**Acceptance Criteria**:
- [ ] The default folders are `%USERPROFILE%\shortcuts\**` only
- [ ] With an empty catalogue, the main search shows one command that names the problem and opens the extension's settings
- [ ] The hint disappears as soon as a configured folder holds a matching file, without a restart
- [ ] With an empty catalogue, the main search also offers "Shortcuts: create example folder"; it creates `%USERPROFILE%\shortcuts` with `Hello.cmd`, `Hello.ps1` and `Open shortcuts folder.lnk`, and the three appear in the main search without a restart
- [ ] Creating the examples leaves every existing file in the folder untouched
- [ ] Without the command, the extension creates no folder and no file
- [ ] Typing "Shortcuts" in the main search finds both commands: both titles start with "Shortcuts:"
- [ ] The README says how to choose folders after installing, and to type *Shortcuts* to find the hint
