# [CPS-015] The logo test does not fail on a locked temp file on Windows

**Status**: Open
**Priority**: Medium
**Component**: `tests/FoldersCatalog.Tests/AssetsTests.cs`
**Related**: [CPS-005](cps-005.md) (the logo test), [CPS-013](cps-013.md) (CI as the gate)

**Summary**:
As the developer, I want the logo test to pass on CI's Windows runner every time, so that a red check means a real defect and not a file lock.

**Description**:
`AssetsTests.Assets_AreTheRenderingOfTheSource` renders the logos into a temp folder and
deletes it afterwards. On CI's Windows runner it failed once (CPS-011's pull request, 2026-11-15)
with `IOException: The process cannot access the file 'LockScreenLogo.scale-200.png' because it
is being used by another process` in `Directory.Delete`, at the end of a run whose comparisons
had passed. A scanner or the indexer holding a freshly written PNG for a moment is the likely
cause; the test's own handles are closed by then. A re-run of the job passed this test.

A way to close it: delete the temp folder in a cleanup that retries for a short time, and does
not fail the test when the folder cannot be removed.

Raised on 2026-11-15, from the closed loop of CPS-011.

**Acceptance Criteria**:
- [ ] A locked file in the render folder does not fail `Assets_AreTheRenderingOfTheSource`
- [ ] The test still fails when a rendered logo differs from the committed one
