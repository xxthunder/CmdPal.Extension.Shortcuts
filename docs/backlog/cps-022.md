# [CPS-022] A failed script keeps its window open

**Status**: Open
**Priority**: Medium
**Component**: `src/CmdPal.Extension.Shortcuts/` (the script start of CPS-009), `README.md`
**Related**: [CPS-009](cps-009.md) (scripts run in `pwsh` and `cmd /c`)

**Summary**:
As a user of Command Palette, I want the console window of a failed script to stay open, so that I can read the error before it closes.

**Description**:
Since CPS-009 a `.ps1` runs as `pwsh -ExecutionPolicy Bypass -File <script>` and a `.bat` or
`.cmd` as `cmd /c <script>`, each in a console window of its own. The window closes as soon as
the script exits. A script that fails prints its error and exits non-zero, so the window closes
with the error in it, and nothing is left to read.

This came up in a UAT on 2026-11-26: a setup script started from the main search failed in a
late step, and its window closed at once. Its `.bat` wrapper ends with `pause` and keeps the
window open, but the main search lists the `.ps1` too, and that is the one the author started.
Each script that wants its output read must add its own wait today, and a `.ps1` started from
the main search has none.

The extension knows the exit code only when it waits for the process; today it starts the
script and returns.

Raised on 2026-11-26.

**Scope Decisions**:
- **Only on failure** (the author, 2026-11-26): the extension keeps the window open when the
  script exits non-zero. A script that wants its output read after a success waits itself, as
  that is script-specific.

**Acceptance Criteria**:
- [ ] A `.ps1` that exits non-zero, started from the main search, keeps its window open until a key is pressed, with a line that names the exit code
- [ ] The same holds for a `.bat` and a `.cmd`
- [ ] A script that exits 0 closes its window as before
- [ ] README names the behaviour next to the script start
